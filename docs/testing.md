# Testing

workers-go targets `GOOS=js GOARCH=wasm`, so most of the code cannot run on a
plain host. Tests are split into layers so that everything that can run under
Node.js does, and only what needs a real Workers runtime goes through
`wrangler dev`.

| Layer | Runs on | What it covers | Command |
| --- | --- | --- | --- |
| L0 pure Go | Node.js (wasm) or host | Logic that never touches JS (`RedirectMode.IsValid`, `Socket` deadlines, `workers-assets-gen`, `handler.go`) | `make test` / `make test-host` |
| L1 fake JS | Node.js (wasm) | Conversions and option builders fed with `js.ValueOf`, plus every binding API (KV / R2 / D1 / Queues / Cache / DO stub / fetch) driven through a fake JS object built with `js.FuncOf` | `make test` |
| L2 binding contract | Node.js (wasm) | The functions Go registers on `context.binding` (`handleRequest`, `runScheduler`, `handleQueueMessageBatch`, `runHonoMiddleware`), invoked the way `worker.mjs` does | `make test` |
| L3 end-to-end | `wrangler dev` (workerd) | Real `worker.mjs` + `app.wasm` fixtures under `e2e/testdata/workers`: HTTP, KV, R2, D1, Queues, cron, Durable Objects, `connect()`, `cf.FromRequest`, version metadata, rate limiting, Images `Info`/resize, Analytics Engine `WriteDataPoint` (the local binding accepts the write and discards the point; there is no local read), Workers AI `Run` (skipped when wrangler has no Cloudflare account), Workflows (`CreateBatch`, `SendEvent`/`WaitForEvent`, pause/resume/terminate), Pages, TinyGo | `make test-e2e` |

`make test-all` runs all of them.

## Commands

```sh
make test            # GOOS=js GOARCH=wasm go test ./... under Node.js (testdata/wasm runner)
make test-host       # host-only packages: . ./cmd/...
make test-e2e        # go test -tags e2e ./e2e/... (starts wrangler dev per fixture)
E2E_TINYGO=1 make test-e2e   # also build and test the TinyGo fixture
make check-generated # regenerate testdata/wasm and cmd/workers-assets-gen/assets, fail on diff
```

`make test-e2e` needs `node`, `pnpm`, and network access the first time
(`pnpm install` in `e2e/`). It fails loudly when they are missing instead of
skipping, so CI cannot pass by accident. Use `-run` to narrow it locally.

## The Node.js runner

`testdata/wasm/` holds a patched copy of Go's `wasm_exec.js` /
`wasm_exec_node.js`. It is generated by `scripts/gen-wasm-exec`
(`make gen-wasm-exec`); never edit it by hand. Compared to upstream it:

- passes a `context` object (`{ binding: {} }`) to `go.run`, because
  `internal/jsutil` reads `globalThis.context.binding` at init;
- provides the `workers.ready` import so tests can call `workers.Ready()`,
  `queues.Consume`, and friends without a `LinkError`; the number of calls is
  exposed as `context.readyCount`;
- defines `globalThis.tryCatch` exactly as `worker.mjs` does.

It deliberately does not polyfill Cloudflare-only globals (`caches`,
`FixedLengthStream`, `WebSocketPair`). Those paths are covered by the E2E
layer.

## `internal/jstest`

Shared helpers for js/wasm tests, modelled on `httptest` / `fstest`:

- `SetRuntimeContext` / `SetEnv` swap `jsutil.RuntimeContext` for the test and
  restore it in `t.Cleanup`, so any API that reads `context.env` can be fed a
  fake binding.
- `NewExecutionContext` records `waitUntil` / `passThroughOnException`.
- `Func`, `Resolved`, `Rejected`, `Await` for Promise plumbing.
- `Uint8Array`, `Bytes`, `ReadableStream`, `ReadAll`, `Request`, `Response`
  for Web-standard values.
- `Binding(t, name)` and `ReadyCount(t)` for L2 tests.
- `AssertObjectEqual` for one-level comparison of `toJS()` results.

Package-specific fakes (`fake_kv_test.go`, `fake_bucket_test.go`,
`fake_d1_test.go`, ...) live next to the package they test.

## Conventions

- Only the standard `testing` package. Table-driven tests use
  `map[string]struct{...}` and `t.Run`; helpers call `t.Helper()`.
- Fakes go in `fake_<subject>_test.go` and are created with `newFake...(t)`.
- Never call `t.Fatalf` (or anything that runs `runtime.Goexit`) inside a
  `js.FuncOf` callback: it runs on the JS event loop, the Promise never settles,
  and the Go side deadlocks. Record with `t.Errorf` and fail afterwards.
- Tests that swap a global (`jsutil.RuntimeContext`, the `caches` variable in
  `cloudflare/cache`, the handler registered by `ServeNonBlock`) must not use
  `t.Parallel()` and must restore the value in `t.Cleanup`.
- Test-only PRs do not change behaviour. When a test exposes a bug, keep the
  test and mark it `t.Skip("known issue: ...")`; fix the bug in a separate PR
  and remove the skip there.
- E2E fixtures stay thin: they expose the SDK call over HTTP and return the raw
  result; assertions live in the Go test.

## Known issues pinned by skipped tests

Search for `t.Skip("known issue` to find them. There are currently none.
